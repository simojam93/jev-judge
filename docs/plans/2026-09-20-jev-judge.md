# jev-judge — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A small, open-sourceable TypeScript library that turns a list of social posts into calibrated, typed judgments via Jev (TypeSafe AI's System One model): per-post relevance score and spam flag, plus a "keep scrolling?" decision — with zero knowledge of where the posts came from.

**Architecture:** One thin client wrapper + two pure functions. All Jev calls go through an injected client interface so unit tests run without network or key. Batch questions per API call (chunked), map Jev's `score` primitive (probability-weighted levels) to 0–100 relevance and its `noul` (0–1) to booleans with confidence.

**Tech Stack:** TypeScript (strict), `@typesafe-ai/sdk` (Node 20+), vitest, tsup for build (ESM+CJS+d.ts). MIT license. This repo goes public at first polished release — write everything as if already public (no PostEcho coupling, no personal data in fixtures).

**Jev API facts (verified against docs.typesafe.ai on 2026-09-20):** npm `@typesafe-ai/sdk`; env `TYPESAFE_API_KEY`; `new TypeSafeClient()`; `client.systemOne({ state, questions })`; question builders include `choice(instructions, criteria)`; raw primitives: `noul` (answer field `noul`, 0–1), `choice` (`choice` + `probabilities` + `confidence`), `score` (`criteria` array of 2–10 ordered levels → answer `score` probability-weighted + `probabilities` + `confidence`). Raw HTTP: `POST https://api.typesafe.ai/v1/systemone`, `Authorization: Bearer <key>`. 429/529 → exponential backoff. If the installed SDK exposes `score`/`noul` builders (check its d.ts — likely alongside `choice`), use them; otherwise construct the raw question objects per the API shapes above and note it.

### Task 2: Types + client interface (TDD throughout)

**Files:** `src/types.ts`, `src/client.ts`, tests colocated `src/*.test.ts`.

```ts
// src/types.ts
export type PostInput = {
  id: string;
  text: string;
  author?: string;
  metrics?: { likes?: number; reposts?: number; replies?: number };
};

export type PostJudgment = {
  id: string;
  relevance: number;        // 0..100, probability-weighted
  relevanceConfidence: number; // 0..1
  isSpam: boolean;          // noul >= spamThreshold
  spamScore: number;        // raw noul 0..1
};

export type JudgeOptions = {
  chunkSize?: number;       // posts per systemOne call, default 8
  spamThreshold?: number;   // default 0.6
  maxRetries?: number;      // default 3 (429/529 backoff)
};

// src/client.ts — the ONLY seam that touches the SDK
export type SystemOneRequest = { state: unknown; questions: Record<string, unknown> };
export type SystemOneAnswer = {
  noul?: number;
  score?: number;
  choice?: string;
  probabilities?: Record<string, number>;
  confidence?: number;
};
export type SystemOneResponse = { answers: Record<string, SystemOneAnswer> };
export interface JevClient { systemOne(req: SystemOneRequest): Promise<SystemOneResponse>; }

export function createJevClient(): JevClient; // wraps @typesafe-ai/sdk TypeSafeClient + backoff on 429/529
```

Backoff: retry `maxRetries` times on errors whose status is 429/529, delays 1s/2s/4s (injectable sleep for tests).

### Task 3: `judgePosts`

**Signature:** `judgePosts(client, { topic, posts, options? }): Promise<PostJudgment[]>`

Per chunk (default 8 posts), ONE `systemOne` call:
- `state`: `{ topic, posts: [{ id, text, author, metrics }...] }`
- `questions`: for each post index i:
  - `rel_${i}`: **score** question — instructions "How relevant and valuable is post {i} for someone hunting inspiration about the topic?" with 5 ordered criteria levels: `["off-topic or useless", "tangentially related", "on-topic but shallow", "relevant and substantive", "exactly the kind of post worth saving"]`. Map: `relevance = round(score_normalized * 100)` where score is normalized over the level range as the API returns it — determine empirically whether `score` comes back already 0–1 or as a level-weighted 0..(levels-1) value; normalize accordingly (document which in a comment) — the unit tests pin the mapping via the fake client.
  - `spam_${i}`: **noul** — "Is post {i} spam, engagement bait, or low-effort filler?" criteria true/false descriptions.

TDD with a fake `JevClient` returning canned answers: mapping correctness (score→0-100, noul→isSpam at threshold), chunking (17 posts, chunkSize 8 → 3 calls, order preserved, ids matched), retry behavior (client throws 429 twice then succeeds), empty input → [].

### Task 4: `shouldContinueScrolling`

**Signature:** `shouldContinueScrolling(client, { topic, seenCount, lastBatch: PostJudgment[] }): Promise<{ continue: boolean; confidence: number }>`

One noul question: state = counts + last batch's relevance distribution (avg, max, spam ratio); instructions "Given diminishing returns so far, is more scrolling likely to surface valuable posts?". Tests with fake client.
